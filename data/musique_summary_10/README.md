# Таблица 11. Три способа дополнить контекст на новых корпусах MuSiQue

Материалы исследования «Формирование контекста LightRAG при ограниченном бюджете токенов».

## Таблица 11. Сравнение трёх условий

После анализа двух исходных условий на тех же 120 вопросах добавили продолжение исходных абзацев в порядке поиска. Поиск LightRAG, набор найденных абзацев, общий префикс и фактическая длина запроса совпадали для трёх условий каждой тройки. В расчёт вошли 122 новых и 238 сохранённых ответов. Для одного вопроса длину запроса сократили во всех трёх условиях и заново получили оба исходных ответа.

**Статус проверки.** Это дополнительный контроль с повторным использованием выборки. В поле `stage: "confirmatory"` в [архивном протоколе](followup/experiment.json) зафиксирован этап запуска по правилам, утверждённым до получения 122 новых ответов. Третье условие выбрали после анализа исходного парного сравнения, поэтому независимая проверка исходной гипотезы на новой выборке остаётся отдельной задачей. Исторический протокол сохранён с исходной контрольной суммой для сверки запросов и результатов.

| Дополнение | Средняя длина контекста, токены | Токенный F1, % |
| --- | ---: | ---: |
| Продолжение исходных абзацев | 3 165,9 | 18,48 |
| Графовые сведения в прозе | 3 165,9 | 25,58 |
| Резюме с учётом вопроса | 3 165,9 | 47,56 |

На RTX 5090 Laptop среднее время 120 вызовов Gemma 4 31B для подготовки резюме составило 9,2 с, медиана — 8,5 с. Время относится к вызову модели резюмирования. [Отдельные замеры](followup/summary_timings.jsonl)

## Исходное парное сравнение

На каждом из 120 вопросов общий поиск LightRAG давал обеим ветвям один набор абзацев. Генератор получал одинаковый префикс и дополнение равной длины в виде резюме или графовых сведений в прозе. Обе ветви использовали Qwen 14B. Резюме составлены моделью Gemma 4 31B по найденным абзацам с учётом вопроса. Из 16 заранее выбранных корпусов взяты первые 10 с завершёнными индексацией и поиском. Сокращение зафиксировано до генерации резюме и ответов.

| Условие | Средняя длина контекста, токены | Токенный F1, % |
| --- | ---: | ---: |
| Графовые сведения в прозе | 3 166,2 | 25,58 |
| Текстовое резюме | 3 166,2 | 47,56 |

Парная разность в пользу резюме составила 21,98 п. п. (95%-й интервал от 14,78 до 28,70 п. п.). Корпуса имеют одинаковый вес. Протокол и JSON-вывод пересчёта используют направление «графовые сведения минус резюме».

### Пересчёт исходного парного сравнения

Команды выполняются из корня репозитория.

```sh
python -m pip install -r requirements.txt
python data/musique_summary_10/reproduce_table11.py
```

Скрипт проверяет контрольные суммы и сверяет запросы и их фактическую длину с журналом Ollama. Токенный F1 и парный бутстреп по корпусам пересчитываются по сохранённым ответам. Для этого достаточно Python и зависимостей репозитория. Веса моделей и GPU нужны для новой генерации.

### Файлы исходного парного сравнения

- [Протокол](experiment.json) и [манифест выборки](cohort.json) содержат условия, параметры моделей, правило отбора и хеши исходных материалов.
- [Вопросы](questions.jsonl), [эталоны по корпусам](evaluation_only/) и [исходные текстовые блоки с вопросами](public/) задают выборку.
- [Ответы и фактические длины](answers.jsonl), [сырой журнал Ollama](raw_answers.jsonl.gz) и [исходный итог](result.json) позволяют проверить пересчёт.
- [Очередь запросов](answer_queue/queue.json.gz), [манифест контекстов](answer_queue/contexts_manifest.json) и [контексты](answer_queue/contexts.zip) сохраняют точные входы генератора.
- [Материалы поиска](retrieval/pools.zip) и [сгенерированные резюме](summaries.zip) содержат сохранённые промежуточные результаты.
